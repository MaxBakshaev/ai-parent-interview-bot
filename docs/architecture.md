# Как устроен новый ИИ-агент — заметки по узлам

Два воркфлоу вместе заменяют один встроенный узел `AI Agent`, который раньше делал всё «под капотом» невидимо. Теперь то же самое собрано вручную из отдельных шагов — зато у нас есть кэширование, полный контроль и видно, что происходит на каждом шаге.

**Главный принцип:** каждое сообщение в Telegram — это **новый, независимый запуск** обоих воркфлоу с нуля. Никакой узел не «помнит» ничего между сообщениями сам по себе — вся память хранится в MongoDB и загружается заново при каждом сообщении.

---

## Воркфлоу 1: «ИИ-бот для опроса родителей v.2» (главный)

Это входная точка — сюда приходят сообщения из Telegram.

```
Telegram Trigger
      │
      ▼
Is Start Command ──(да, это /start)──► Send Start Greeting ──► конец
      │
   (нет, обычное сообщение)
      ▼
Send a chat action1
      │
      ▼
Get Conversation History
      │
      ▼
Prepare Messages
      │
      ▼
Call Claude Agent Turn   ← здесь мы уходим во ВТОРОЙ воркфлоу и ждём ответа
      │
      ▼
Prepare History For Storage
      │
      ▼
Save Conversation History
      │
      ▼
Sanitize AI Output
      │
      ▼
Send a chat action  →  Wait  →  Send a text message
```

### Узлы по порядку

**Telegram Trigger** — принимает любое новое сообщение от пользователя. Ничего не меняли, стандартный узел.

**Is Start Command** — проверяет, не является ли сообщение командой `/start`. Если да — сразу уходит в `Send Start Greeting`, минуя всю остальную логику и ИИ. Это сделано специально: приветствие уходит мгновенно, без похода к модели.

**Send Start Greeting** — жёстко прописанный текст приветствия, отправляется напрямую в Telegram. ИИ здесь вообще не участвует — поэтому и быстро.

**Send a chat action1** — показывает пользователю «печатает…» в Telegram, пока идёт вся обработка ниже.

**Get Conversation History** (MongoDB) — ищет в базе `n8n_bot_memory`, коллекция `claude_agent_history`, документ с этим `chat_id`. Если это первый разговор — ничего не найдёт, но всё равно отдаст 1 «пустой» элемент дальше (настройка `alwaysOutputData` — без неё цепочка бы просто остановилась для новых пользователей, это мы уже проходили раньше на похожей проблеме).

**Prepare Messages** (Code) — берёт найденную историю (или пустой список, если её нет), добавляет к ней **текущее** сообщение пользователя и упаковывает всё в одну строку `messages_json` — это тот самый формат, который понимает Anthropic API.

**Call Claude Agent Turn** (Execute Workflow) — передаёт эстафету во второй воркфлоу и ждёт, пока тот вернёт готовый ответ. Внутри может произойти много шагов (см. ниже), но снаружи это выглядит как один вызов.

**Prepare History For Storage** (Code) — берёт то, что вернул второй воркфлоу (`text` и обновлённый `messages`), готовит для записи в базу.

**Save Conversation History** (MongoDB, upsert) — записывает обновлённую историю обратно в ту же коллекцию, по ключу `chat_id`. В следующий раз `Get Conversation History` найдёт именно её.

**Sanitize AI Output** (Code) — подстраховка: если модель вдруг «проговорится» сырым текстом вызова инструмента вместо настоящего вызова — эта защита вырежет мусор до того, как он попадёт в Telegram.

**Send a chat action → Wait → Send a text message** — имитация набора текста (пауза 2-5 сек в зависимости от длины ответа) и сама отправка сообщения пользователю.

## Воркфлоу 2: «Claude Agent Turn» (движок)

Это «мозг» — здесь происходит разговор с самим Anthropic API и выполнение инструментов. Этот воркфлоу может **вызывать сам себя** — это единственная сложная идея во всей системе, дальше разберём почему.

```
When Called
    │
    ▼
Build Anthropic Request
    │
    ▼
Call Claude API  ──────────► (реальный запрос в Anthropic)
    │
    ▼
Parse Claude Response
    │
    ▼
Has Tool Use? ──(нет, просто текст)──────────────────► Return Result
    │
  (да, модель хочет вызвать инструмент)
    ▼
Is Save Interview? ──(да)──► Execute: Save Interview Results ──┐
    │                                                            │
  (нет, это schedule_reminder)                                  │
    ▼                                                            ▼
Execute: Schedule Reminder ──► Build Tool Result (Reminder)    Build Tool Result (Save)
                                        │                              │
                                        └──────────┬───────────────────┘
                                                    ▼
                                Append Tool Result & Prep Recursion
                                                    │
                                                    ▼
                                       Under Iteration Limit?
                                          │                    │
                                      (да, <6)             (нет, ≥6 — аварийный стоп)
                                          ▼                    ▼
                                Call Self (Recurse)    Force Stop Fallback
                                          │                    │
                                          └─────────┬──────────┘
                                                     ▼
                                              Return Result
```

### Узлы по порядку

**When Called** (Execute Workflow Trigger) — точка входа. Принимает три параметра: `chat_id`, `messages_json` (вся история разговора одной строкой) и `iteration` (счётчик, см. ниже).

**Build Anthropic Request** (Code) — самый важный узел. Собирает тело запроса для Anthropic API:
- `system` — весь системный промпт (правила, шаги интервью и т.д.), **статичный**, одинаковый для всех пользователей — это специально сделано ради кэша.
- `tools` — описание `save_interview_results` (58 полей) и `schedule_reminder`.
- `messages` — история разговора.
- В двух местах стоят метки `cache_control` — это то, что заставляет Anthropic кэшировать промпт+инструменты и накопленную историю, вместо того чтобы пересчитывать всё заново на каждое сообщение. Именно из-за этого стоимость упала с ~$1.5 до заметно меньшей суммы за диалог.

**Call Claude API** (HTTP Request) — собственно вызов `https://api.anthropic.com/v1/messages`. Использует те же учётные данные (credential), что раньше использовал встроенный узел `Anthropic Chat Model`.

**Parse Claude Response** (Code) — разбирает, что ответила модель: просто текст, или текст + запрос на вызов инструмента. Тут же добавляет ответ модели в историю разговора.

**Has Tool Use?** (IF) — развилка: инструмент нужен вызывать или нет.
- **Нет** → сразу к `Return Result` — разговор на этом ходе закончен, отдаём текст пользователю.
- **Да** → идём выполнять инструмент.

**Is Save Interview?** (IF) — если инструмент один, ветвление по имени: `save_interview_results` или `schedule_reminder`.

**Execute: Save Interview Results / Execute: Schedule Reminder** — реальный вызов соответствующего под-воркфлоу (те же самые, что были и раньше, мы их не трогали). `chat_id` сюда подставляется автоматически из данных, известных серверу — модели вообще не нужно про него знать или его передавать.

**Build Tool Result (Save) / (Reminder)** (Code) — короткое текстовое подтверждение («Сохранено.» / «Напоминание запланировано.»), которое нужно вернуть модели как результат выполнения инструмента (так того требует протокол Anthropic — на каждый `tool_use` должен прийти `tool_result`).

**Append Tool Result & Prep Recursion** (Code) — добавляет этот `tool_result` в историю и увеличивает счётчик `iteration` на 1.

**Under Iteration Limit?** (IF) — проверка «не зациклились ли мы». Лимит — 6 повторов на один ход. Обычно хватает 1-2, поэтому это скорее аварийный тормоз, чем реально работающая логика.

**Call Self (Recurse)** (Execute Workflow) — самое необычное место: этот узел вызывает **тот же самый воркфлоу заново**, с уже обновлённой историей (в которой появился `tool_result`). Зачем: после вызова инструмента модель ещё не сказала пользователю ни слова текстом — надо ещё раз спросить у неё, что писать дальше, уже зная, что инструмент отработал. Это как бы «повторный вопрос» модели: «данные сохранены, теперь что скажешь пользователю?» — и весь путь (`Build Anthropic Request → Call Claude API → Parse Claude Response → Has Tool Use?`) проходит заново, но уже обычно без вызова инструмента, поэтому доходит до `Return Result` с готовым текстом.

**Force Stop Fallback** (Code) — если лимит в 6 повторов всё же исчерпан (что-то пошло совсем не так) — вместо зависания отдаём пользователю вежливую фразу «разговор затянулся, продолжим по следующему сообщению».

**Return Result** (NoOp) — единая точка выхода. Всё, что сюда приходит (текст + история), уходит обратно в главный воркфлоу как результат `Call Claude Agent Turn`.

## Путь одного сообщения от начала до конца (пример)

Пользователь пишет: *«Меня зовут Анна, школа Ромашка, 3 класс»*

1. Приходит в `Telegram Trigger` → не `/start` → идёт по обычной ветке.
2. `Get Conversation History` находит в MongoDB его прошлую переписку (если есть).
3. `Prepare Messages` добавляет это сообщение в конец истории.
4. `Call Claude Agent Turn` уходит во второй воркфлоу:
   - `Build Anthropic Request` собирает запрос.
   - `Call Claude API` — модель отвечает: *"Спасибо! Хочу вызвать save_interview_results с parent_name=Анна, school_name=Ромашка, child_grade=3"*.
   - `Parse Claude Response` видит `tool_use` → идём выполнять.
   - `Execute: Save Interview Results` реально записывает эти поля в Google-таблицу.
   - `Append Tool Result & Prep Recursion` добавляет «Сохранено.» в историю, iteration = 1.
   - `Under Iteration Limit?` (1 < 6) → `Call Self (Recurse)` — воркфлоу вызывает сам себя заново.
   - **Внутри этого повторного вызова**: `Build Anthropic Request` снова собирает запрос (уже с `tool_result` в истории) → `Call Claude API` — на этот раз модель просто отвечает текстом: *"Спасибо, Анна! Скажите, вы постоянно живёте в этой стране?"* → `Has Tool Use?` = нет → сразу `Return Result`.
   - Этот результат «всплывает» обратно как ответ первого вызова `Call Self (Recurse)` → тоже в `Return Result`.
5. Главный воркфлоу получает `{text: "Спасибо, Анна!...", messages: [...]}`.
6. `Save Conversation History` записывает обновлённую историю в MongoDB.
7. `Sanitize AI Output` проверяет текст на мусор.
8. Пользователь видит «печатает…», через пару секунд получает сообщение.

Итого на одно сообщение пользователя ушло **два обращения к Anthropic API** (одно с вызовом инструмента, второе — чисто текстовый ответ) — но благодаря кэшированию оба обращения дешёвые, потому что почти всё в них берётся из кэша.

## Что делать, если что-то не работает

- **Ошибка в `Call Claude API`** → смотрите `Parse Claude Response`, скорее всего там `type: 'error'` — сработает встроенная заглушка про «пропала связь».
- **Поле не сохранилось в таблицу** → смотрите вход/выход `Execute: Save Interview Results` — что реально пришло в `tool_input`.
- **Разговор оборвался/зациклился** → проверьте `iteration` на выходе `Append Tool Result & Prep Recursion` — если он растёт ненормально быстро, смотрите, почему модель постоянно вызывает инструмент вместо текста.
- **Старая история не подхватывается** → проверьте `Get Conversation History`, что `chat_id` в запросе точно совпадает по формату (строка) с тем, что лежит в базе.
